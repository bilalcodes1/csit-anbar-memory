# ذاكرة الكلية

أرشيف رقمي عربي RTL لدفعات **كلية علوم الحاسوب وتكنولوجيا المعلومات – جامعة الأنبار**. يحفظ الدفعات والألبومات والصور وأسماء الطلبة، مع لوحة إدارة آمنة مرتبطة فعليًا بـ Cloudflare D1 وR2.

## الروابط

- الموقع العام: <https://csit-anbar-memory.pages.dev/>
- لوحة الإدارة: <https://csit-anbar-memory.pages.dev/admin>
- مشاركة دفعة مباشرة: `https://csit-anbar-memory.pages.dev/batch/<year>`

## المزايا

- واجهة عربية RTL متجاوبة مع الهاتف والكمبيوتر.
- عرض الدفعات المنشورة مع الألبومات والصور والأسماء.
- رابط مباشر قابل للمشاركة يفتح الدفعة المطلوبة فورًا.
- مشاركة أصلية على الهاتف أو نسخ الرابط تلقائيًا على المتصفحات الأخرى.
- لوحة إدارة للمدير والمشرفين.
- إدارة كاملة للدفعات والألبومات والطلبة.
- رفع جماعي حتى 50 صورة، مع تقدم مستقل وأربع عمليات رفع متوازية.
- دعم JPG وPNG وWebP حتى 20 ميغابايت للصورة.
- معاينة الصور صورة بصورة.
- تحديد صورة أو تحديد الكل وحذف جماعي.
- استبدال الصورة مع الحفاظ على بيانات الألبوم.
- تعديل النص البديل والوصف والترتيب وحالة النشر.
- تخزين الصور في Cloudflare R2.
- بيانات المحتوى في Cloudflare D1.
- دخول باسم مستخدم وكلمة مرور، مع QR للأجهزة الموثوقة صالح لمدة 90 يومًا وقابل للإلغاء.
- سجل عمليات إداري وصفحات لمكتبة الصور مع إحصاءات للملفات المعروضة.

## عرض الجامعة

من مجلد المشروع، شغّل الأمر التالي باستخدام Node.js 22 أو أحدث. يجهّز Wrangler قاعدة وملفات محلية معزولة، ويطبع عنواني الأرشيف والإدارة وبيانات دخول حساب العرض.

```bash
sh scripts/demo.sh
```

1. افتح الأرشيف، وابحث بالسنة، ثم افتح دفعة واستعرض الألبوم والأسماء.
2. افتح الإدارة من الرابط المطبوع، ثم اعرض حالة النشر ومكتبة الصور وسجل العمليات.
3. أضف دفعة تجريبية كمسودة، ثم انشرها وأعد تحميل الأرشيف لمشاهدة ظهورها.
4. أوقف الخادم بـ `Ctrl+C`. تبقى بيانات العرض تحت `.wrangler/demo` على الجهاز.

الصور في العرض مأخوذة من ملفات المشروع والأسماء توضيحية. يعتمد الموقع العام على سجلات Cloudflare المنشورة. قبل الإطلاق الرسمي تُعتمد المواد التي تظهر للزوار وتحدد الكلية قناة طلبات التصحيح والحذف.

## التشغيل المحلي للمطور

```bash
sh scripts/build.sh
npx wrangler d1 migrations apply csit-anbar-memory --local
npx wrangler pages dev dist
```

ضع رمز التهيئة المحلي في `.dev.vars` لتجربة إنشاء أول مدير. يعمل الاختبار التالي مع نسخة D1 وR2 محلية معزولة. ينشئ بيانات اختبار ويتحقق من النشر والخصوصية وإدارة الألبومات والصور والأسماء وصلاحيات المستخدمين وجلسات QR.

```bash
ARCHIVE_TEST_SETUP_TOKEN="رمز-التهيئة-المحلي" node scripts/smoke.mjs
```

## اختبار ألبومات الدفعات

يدعم اختبار HTTP صورة فعلية من الجهاز عبر متغير `ARCHIVE_TEST_IMAGE` (PNG أو JPEG أو WebP). ينشئ دفعة وألبومًا محليين عبر واجهات الإدارة، ويفحص حجب المسودة ثم ظهورها للزوار بعد النشر.

## إعداد Cloudflare

1. أنشئ مشروع Pages باسم `csit-anbar-memory`.
2. أنشئ D1 باسم `csit-anbar-memory` واربطه في `wrangler.toml`.
3. أنشئ R2 bucket باسم `csit-anbar-memory-images`.
4. طبّق ترحيلات D1:

   ```bash
   npx wrangler d1 migrations apply csit-anbar-memory --remote
   ```

5. أضف السر `ADMIN_SETUP_TOKEN` إلى إعدادات Pages Functions، ولا تضع قيمته في Git.
6. شغّل إنشاء المدير الأول مرة واحدة عبر `POST /api/auth/setup` باستخدام Authorization Bearer token.
7. بعد إنشاء المدير، أزل أو دوّر `ADMIN_SETUP_TOKEN`.
8. افتح `/admin` وسجّل الدخول، ثم أضف الدفعات والألبومات والصور.

اضبط أمر البناء `sh scripts/build.sh` ومجلد المخرجات `dist` إذا كان النشر مرتبطًا بـ GitHub. للنشر اليدوي شغّل:

```bash
sh scripts/build.sh
npx wrangler pages deploy dist --project-name csit-anbar-memory --branch main
```

## واجهات API العامة

| الطريقة | المسار | الوظيفة |
|---|---|---|
| GET | `/api/batches` | الدفعات المنشورة |
| GET | `/api/batches/:year` | تفاصيل دفعة وألبوماتها وصورها |
| GET | `/media/:key` | بث صورة من R2 |

## واجهات API الإدارية

جميعها تتطلب جلسة دخول، وبعض عمليات الحذف تتطلب دور المدير:

- `/api/admin/overview` — الإحصاءات والدفعات وسجل العمليات وملفات R2.
- `/api/admin/batches` و`/api/admin/batches/:id` — إنشاء وتعديل وحذف الدفعات.
- `/api/admin/albums` — إدارة الألبومات.
- `/api/admin/students` — إدارة أسماء الطلبة.
- `/api/admin/upload` — رفع صورة أو استبدالها.
- `/api/admin/media` — استعراض ملفات R2 وحذف ملف أو عدة ملفات.
- `/api/admin/photos` — تعديل بيانات الصورة وحذفها.
- `/api/admin/users` — إدارة المشرفين والمديرين.
- `/api/auth/device` — إنشاء واستعراض وإلغاء أجهزة QR الموثوقة.

## النشر والمحتوى

تبدأ الصور الجديدة كمسودات. تظهر الصورة في المعرض العام عند نشر الصورة وألبومها ودفعتها. اختيار ملف كغلاف لدفعة منشورة يجعل الغلاف ظاهرًا للزوار. الأسماء تُنشر بشكل مستقل داخل الدفعة المنشورة.

قبل النشر العام:

- اعتمد الصور والأسماء من الجهة المسؤولة.
- لا ترفع أرقام الهواتف أو العناوين أو بيانات شخصية غير لازمة.
- راجع `PRIVACY.md` وأضف وسيلة تواصل رسمية لطلبات التصحيح والحذف.

## الأمان

- تُخزّن مشتقات كلمات المرور باستخدام PBKDF2. يدعم تسجيل الدخول المشتقات من النسخ السابقة ويحدثها عند نجاح التحقق.
- جلسات الإدارة داخل HttpOnly Secure cookies.
- رموز QR لا تحتوي كلمة المرور، بل رمز جهاز عشوائي مجزأ في D1.
- أسرار Cloudflare مستثناة من Git عبر `.gitignore`.
- لا تضع بيانات اعتماد حقيقية أو رموز API في المستودع.
